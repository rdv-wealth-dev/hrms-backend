## 💰 1. PAYROLL MODULE — Complete Overhaul

### 1a. Statutory Calculation Engine (`payroll.util.ts`)

**Problem before**: Payroll calculations were hardcoded approximations — flat PF percentages, no TDS logic, no PT/LWF slabs, no statutory wage ceiling.

**What was built**:

#### Provident Fund (PF) — EPF Act 1952 Compliant
- Caps calculation at statutory wage ceiling (configurable, default ₹15,000).
- Correctly splits employer contribution into:
  - **EPS (Pension)**: 8.33% capped at ₹1,250/month
  - **EPF**: 3.67%
- Adds employer **Admin Charge** (0.5%) and **EDLI Insurance** (0.5%).

#### Professional Tax (PT) — State Slab Driven
- Reads from `ProfessionalTaxConfig` collection (per state).
- Supports month-specific rates (e.g. Maharashtra February rule: ₹300 instead of ₹200).
- Falls back gracefully if no PT config found for the state.

#### Labour Welfare Fund (LWF)
- Reads from `LWFConfigModel` collection per state.
- Only deducts in HR-configured contribution months (e.g. June + December).
- Returns both employee and employer share.

#### TDS / Income Tax — 12-Step Slab Engine
- Supports **Old Regime** vs **New Regime** via `TaxDeclarationModel`.
- Standard Deduction: ₹75,000 (New) / ₹50,000 (Old).
- Applies exemptions: **HRA**, **Section 80C** (EPF + investments ≤ ₹1.5L), **80D** (health ≤ ₹50k), **80CCD(1B)** (NPS ≤ ₹50k), **Home Loan Interest** (≤ ₹2L).
- **PAN Guard (Section 206AA)**: flat 20% TDS if no PAN on file.
- Monthly TDS = `(Annual Tax + 4% Cess) / remaining months`.

#### Attendance Summary Builder
- **Before**: N+1 query pattern — one DB query per day per employee to check leave.
- **After**: Bulk-fetch (2 queries total regardless of days), in-memory date map resolution. ~96% DB query reduction.

**Files changed**: `payroll.util.ts` (+624 lines), `statutory-config.model.ts` (new — 180 lines)

## ⏱️ 2. ATTENDANCE MODULE

### 2a. OT Auto-Computation on Checkout

**Before**: `OvertimeService.computeForDay()` was never called — overtime was never automatically computed.

**After**: `attendance.service.ts` now calls `computeForDay()` immediately after:
- `CHECK_OUT` punch is processed.
- A **manual entry** is saved by HR (if `workedMinutes > 0`).

**Safety**: OT computation is wrapped in try-catch — any OT failure will **not** block the checkout from succeeding.

**Files changed**: `attendance.service.ts` (+44 lines), `overtime.service.ts` (+4 lines)

## 🎉 3. HOLIDAY MANAGEMENT MODULE

### 3a. Hierarchical Holiday Resolution Engine

Built a full multi-layer priority merge engine (`holiday-resolution.engine.ts`):

```
Priority: BRANCH > STATE > COUNTRY > GLOBAL
```

- On the same date, higher scope wins (BRANCH-level holiday overrides a COUNTRY-level one).
- Results are **LRU-cached** per `tenantId + branchId + year` (30-min TTL).
- Supports **deduplication** — same date appears only once in the final resolved calendar.

**New endpoint**: `GET /leave/holidays/resolve?branchId=<id>&year=2026`

**New supporting files**: `holiday-resolution.engine.ts` (138 lines), `state-code-mapper.util.ts` (37 lines), `state-mapper.config.ts` (40 lines)

---

### 3b. Dynamic Statutory Seeder

**Before**: Hardcoded static list of Indian national holidays.

**After**: Uses the `date-holidays` npm library to dynamically fetch official statutory public holidays for **any country / state / canton** for a rolling 2-year window.

- Supports state-level seeding for federal countries (e.g. India states, Swiss cantons).
- **Idempotent** — safe to run multiple times (uses MongoDB `$setOnInsert` upsert).
- Auto-triggered on branch create/update if the country code changes.

**Files changed**: `holiday.seed.ts` (full rewrite — 151 lines)

---

### 3c. Branch HR Holiday Scoping Fix

**Problem**: Branch HR users could see **all** BRANCH-scope holidays from every branch in the tenant.

**Fix in `holiday.repository.ts` `findForYear()`**:

| User Type | Holiday Visibility |
|---|---|
| HQ / ORG_ADMIN | All scopes, all branches |
| Branch HR / Admin | GLOBAL + COUNTRY + STATE (shared) **+** only their own branch's BRANCH holidays |

**Files changed**: `holiday.repository.ts` (+18 lines)

---

### 3d. Seed Endpoint — Lock to Org Country Code

**Before**: `POST /leave/holidays/seed-default?countryCode=US` — anyone could seed holidays for any country.

**After**: `?countryCode` param is completely removed. Country is always derived from the org's registered locale. Returns `400` if org has no country code configured.

**Files changed**: `holiday.controller.ts` (+10 lines, -7 lines)
